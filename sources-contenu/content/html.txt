§§chapter html-bases
part: html
title: Premiers pas en HTML
subtitle: Balises, éléments, attributs et squelette d'une page
duration: 1 h
feature: La coque de l'application (index.html)
§intro
<p>Le <strong>HTML</strong> (HyperText Markup Language) n'est pas un langage de programmation : c'est un langage de <strong>description</strong>. Il dit au navigateur « ceci est un titre », « ceci est un paragraphe », « ceci est un bouton ».</p>
<p>On écrit le HTML avec des <strong>balises</strong> entre chevrons. La plupart vont par deux : une balise ouvrante <code>&lt;p&gt;</code> et une balise fermante <code>&lt;/p&gt;</code>. Le tout (balises + contenu) s'appelle un <strong>élément</strong>.</p>
<p>Une balise peut porter des <strong>attributs</strong> qui ajoutent une information : <code>&lt;html lang="fr"&gt;</code> indique que la page est en français. Certaines balises sont <strong>vides</strong> (sans fermeture) : <code>&lt;meta&gt;</code>, <code>&lt;img&gt;</code>, <code>&lt;br&gt;</code>.</p>
<div class="analogy"><strong>Image mentale :</strong> le HTML est le squelette de la page, le CSS est la peau et les vêtements, le JavaScript est les muscles qui la font bouger.</div>
§example html
<!DOCTYPE html>                 <!-- 1. Je déclare un document HTML5 -->
<html lang="fr">                <!-- 2. Racine de la page, en français -->
  <head>                        <!-- 3. Informations pour le navigateur (invisibles) -->
    <meta charset="UTF-8">      <!-- Encodage : accents corrects -->
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Ondea Commandes</title>   <!-- Titre de l'onglet -->
    <link rel="stylesheet" href="css/style.css">  <!-- Feuille de style -->
  </head>
  <body>                        <!-- 4. Tout ce qui est visible -->
    <h1>Ondea Commandes</h1>
    <p>Gestion des commandes pour TPE et PME.</p>
    <script src="js/app.js" defer></script>  <!-- JS chargé après le HTML -->
  </body>
</html>
§explain
<ul>
<li><code>&lt;!DOCTYPE html&gt;</code> doit être la toute première ligne : sans elle, le navigateur passe en « mode bizarre » (quirks).</li>
<li><code>&lt;head&gt;</code> contient les <em>métadonnées</em> : encodage, titre de l'onglet, liens vers le CSS. Rien n'y est affiché dans la page.</li>
<li><code>&lt;meta name="viewport"&gt;</code> est indispensable pour que la page s'adapte aux smartphones.</li>
<li><code>&lt;body&gt;</code> contient tout ce que l'utilisateur voit.</li>
<li>L'attribut <code>defer</code> sur <code>&lt;script&gt;</code> attend que tout le HTML soit lu avant d'exécuter le JavaScript.</li>
<li>Les commentaires <code>&lt;!-- ... --&gt;</code> ne sont pas affichés : ils servent à expliquer le code.</li>
<li>On <strong>indente</strong> (décale) les éléments enfants de 2 espaces pour voir l'imbrication d'un coup d'œil.</li>
</ul>

§§chapter html-semantique
part: html
title: HTML5 sémantique
subtitle: header, nav, main, aside, section, article, footer
duration: 1 h 30
feature: Mise en page : barre latérale, barre supérieure, zone de contenu
§intro
<p>Une balise <strong>sémantique</strong> a un <em>sens</em>. <code>&lt;div&gt;</code> ne veut rien dire (c'est une boîte neutre), alors que <code>&lt;nav&gt;</code> veut dire « ceci est une navigation ».</p>
<p>Pourquoi c'est important ? Les lecteurs d'écran proposent de « sauter à la navigation » ou « au contenu principal » ; Google comprend mieux la page ; et vos collègues relisent le code plus vite.</p>
<p>Les zones principales s'appellent des <strong>landmarks</strong> (points de repère) : <code>&lt;header&gt;</code> (en-tête), <code>&lt;nav&gt;</code> (menu), <code>&lt;main&gt;</code> (contenu principal, <strong>un seul</strong> par page), <code>&lt;aside&gt;</code> (contenu annexe), <code>&lt;footer&gt;</code> (pied). À l'intérieur : <code>&lt;section&gt;</code> regroupe un thème avec son titre, <code>&lt;article&gt;</code> est un bloc autonome (une carte commande, un billet).</p>
§example html
<body>
  <!-- Barre latérale : logo + menu principal -->
  <aside class="sidebar">
    <p class="logo">Ondea Commandes</p>
    <nav aria-label="Menu principal">
      <ul>
        <li><a href="#/tableau-de-bord">Tableau de bord</a></li>
        <li><a href="#/commandes">Commandes</a></li>
        <li><a href="#/clients">Clients</a></li>
      </ul>
    </nav>
  </aside>

  <!-- En-tête de la zone de travail -->
  <header class="topbar">
    <h1>Tableau de bord</h1>
  </header>

  <!-- Contenu principal : un seul <main> -->
  <main id="contenu">
    <section aria-labelledby="titre-kpi">
      <h2 id="titre-kpi">Indicateurs du jour</h2>
      <article class="kpi">
        <h3>Commandes en attente</h3>
        <p>12</p>
      </article>
    </section>
  </main>

  <footer>© 2026 Ondea Web Studio</footer>
</body>
§explain
<ul>
<li><code>&lt;aside&gt;</code> contient ici la barre latérale ; <code>&lt;nav&gt;</code> le menu. Le <code>aria-label</code> nomme ce menu pour les lecteurs d'écran.</li>
<li>Le menu est une <strong>liste</strong> <code>&lt;ul&gt;</code> de liens : un lecteur d'écran annonce « liste, 3 éléments ».</li>
<li><code>&lt;main id="contenu"&gt;</code> est unique ; l'<code>id</code> permettra un lien d'évitement « Aller au contenu ».</li>
<li><code>&lt;section aria-labelledby="titre-kpi"&gt;</code> : la section prend pour nom le texte de son titre.</li>
<li>Chaque indicateur est un <code>&lt;article&gt;</code> : il a du sens tout seul.</li>
<li>La hiérarchie des titres <code>h1 → h2 → h3</code> ne saute pas de niveau.</li>
</ul>

§§chapter html-contenus
part: html
title: Textes, listes, liens et images
subtitle: Les briques de contenu d'un écran
duration: 1 h
feature: Tableau de bord et fiches produits
§intro
<p>Six familles de balises suffisent pour 90 % des contenus :</p>
<ul>
<li><strong>Titres</strong> <code>&lt;h1&gt;</code> à <code>&lt;h6&gt;</code> : le plan de la page.</li>
<li><strong>Paragraphes</strong> <code>&lt;p&gt;</code> et mise en valeur <code>&lt;strong&gt;</code> (important) ou <code>&lt;em&gt;</code> (accentué).</li>
<li><strong>Listes</strong> : <code>&lt;ul&gt;</code> (à puces), <code>&lt;ol&gt;</code> (numérotée), chaque élément dans <code>&lt;li&gt;</code>.</li>
<li><strong>Liens</strong> <code>&lt;a href="..."&gt;</code> : vers une autre page, une ancre <code>#id</code>, un e-mail <code>mailto:</code> ou un téléphone <code>tel:</code>.</li>
<li><strong>Images</strong> <code>&lt;img src alt&gt;</code> : <code>alt</code> décrit l'image pour qui ne la voit pas.</li>
<li><strong>Figures</strong> <code>&lt;figure&gt;</code> + <code>&lt;figcaption&gt;</code> : une image avec sa légende.</li>
</ul>
<p>Règle d'or : on choisit la balise pour son <strong>sens</strong>, jamais pour son apparence (le CSS s'en chargera).</p>
§example html
<article class="fiche-produit">
  <!-- Image : alt décrit ce que montre la photo -->
  <figure>
    <img src="perceuse.jpg" alt="Perceuse sans fil bleue avec sa batterie"
         width="320" height="240" loading="lazy">
    <figcaption>Photo fournisseur</figcaption>
  </figure>

  <h2>Perceuse sans fil 18 V</h2>
  <p>Référence <strong>PER-18V-01</strong> — <em>stock faible</em>.</p>

  <!-- Liste à puces : caractéristiques sans ordre -->
  <ul>
    <li>2 batteries incluses</li>
    <li>Garantie 3 ans</li>
  </ul>

  <!-- Liste numérotée : les étapes ont un ordre -->
  <ol>
    <li>Commander</li>
    <li>Préparer</li>
    <li>Expédier</li>
  </ol>

  <p>Fournisseur : <a href="mailto:contact@outipro.fr">contact@outipro.fr</a>
     — <a href="tel:+33494000000">04 94 00 00 00</a></p>
</article>
§explain
<ul>
<li><code>width</code> et <code>height</code> sur <code>&lt;img&gt;</code> réservent la place : la page ne « saute » pas au chargement.</li>
<li><code>loading="lazy"</code> ne charge l'image que lorsqu'elle approche de l'écran.</li>
<li>Une image purement décorative reçoit <code>alt=""</code> (vide) : le lecteur d'écran l'ignore.</li>
<li><code>&lt;strong&gt;</code> = importance ; <code>&lt;b&gt;</code> = simple gras visuel (à éviter).</li>
<li>Les liens <code>mailto:</code> et <code>tel:</code> ouvrent la messagerie ou le téléphone sur mobile.</li>
<li>Le texte d'un lien doit avoir du sens seul : « Voir la commande CMD-42 » plutôt que « cliquez ici ».</li>
</ul>

§§chapter html-navigation
part: html
title: Navigation et liens d'application
subtitle: Menu, page courante, routes par hash
duration: 45 min
feature: Navigation entre les écrans
§intro
<p>Une application web d'une seule page (on dit <strong>SPA</strong>, Single Page Application) ne recharge pas la page à chaque clic. Elle utilise des liens qui changent seulement la partie après le <code>#</code> de l'adresse : <code>index.html#/commandes</code>, <code>index.html#/clients</code>.</p>
<p>Le HTML prépare le terrain : un <code>&lt;nav&gt;</code>, une liste de liens, et l'attribut <code>aria-current="page"</code> sur le lien de l'écran affiché. C'est lui qui dit à un lecteur d'écran « page actuelle », et le CSS peut s'en servir pour le surligner.</p>
<p>On ajoute aussi un <strong>lien d'évitement</strong> tout en haut : « Aller au contenu ». Au clavier, c'est le premier élément atteint avec Tab : il évite de traverser tout le menu.</p>
§example html
<!-- Lien d'évitement : premier élément focusable de la page -->
<a class="skip-link" href="#contenu">Aller au contenu</a>

<nav id="main-nav" aria-label="Menu principal">
  <ul>
    <!-- data-route : information personnalisée lue par JavaScript -->
    <li><a class="nav-link" href="#/tableau-de-bord" data-route="tableau-de-bord"
           aria-current="page">Tableau de bord</a></li>
    <li><a class="nav-link" href="#/commandes" data-route="commandes">Commandes</a></li>
    <li><a class="nav-link" href="#/preparation" data-route="preparation">Préparation</a></li>
    <li><a class="nav-link" href="#/livraisons" data-route="livraisons">Livraisons</a></li>
  </ul>
</nav>

<main id="contenu" tabindex="-1">…</main>
§explain
<ul>
<li><code>href="#/commandes"</code> : le navigateur ne recharge pas, il change l'adresse et déclenche l'événement <code>hashchange</code> qu'écoute le JavaScript.</li>
<li>Les attributs <code>data-*</code> (ici <code>data-route</code>) stockent une donnée libre, lisible en JS via <code>element.dataset.route</code>.</li>
<li><code>aria-current="page"</code> ne doit être que sur <strong>un</strong> lien à la fois.</li>
<li><code>tabindex="-1"</code> sur <code>&lt;main&gt;</code> permet de lui donner le focus par programme après un changement d'écran.</li>
<li>Le lien d'évitement est caché visuellement mais réapparaît quand il reçoit le focus clavier.</li>
</ul>

// Ce script surligne le lien correspondant à l'adresse (#/...)
function majMenu() {
  const route = location.hash.replace('#/', '') || 'tableau-de-bord';
  document.querySelectorAll('nav a').forEach((a) => {
    if (a.dataset.route === route) a.setAttribute('aria-current', 'page');
    else a.removeAttribute('aria-current');
  });
  document.getElementById('titre').textContent = document.querySelector('nav a[aria-current]').textContent;
}
window.addEventListener('hashchange', majMenu);
majMenu();

§§chapter html-formulaires
part: html
title: Formulaires
subtitle: label, input, select, textarea, fieldset et validation native
duration: 2 h
feature: Connexion et fiche client
§intro
<p>Un formulaire permet à l'utilisateur d'envoyer des informations : se connecter, créer un client, saisir une commande.</p>
<p>Trois règles pour un formulaire professionnel :</p>
<ol>
<li><strong>Chaque champ a un <code>&lt;label&gt;</code></strong> relié par <code>for</code> = <code>id</code> du champ. Cliquer sur le label met le curseur dans le champ, et le lecteur d'écran lit le label.</li>
<li><strong>Le bon type</strong> : <code>email</code>, <code>tel</code>, <code>number</code>, <code>date</code>, <code>password</code>… Sur mobile, le clavier s'adapte.</li>
<li><strong>La validation native</strong> : <code>required</code>, <code>minlength</code>, <code>min</code>, <code>max</code>, <code>pattern</code>. Le navigateur bloque l'envoi si c'est invalide.</li>
</ol>
<p>On regroupe les champs liés dans un <code>&lt;fieldset&gt;</code> avec une légende <code>&lt;legend&gt;</code>.</p>
§example html
<form id="form-connexion" novalidate>
  <h1>Connexion</h1>

  <!-- for="identifiant" relie le label au champ id="identifiant" -->
  <label for="identifiant">Identifiant</label>
  <input id="identifiant" name="username" type="text"
         autocomplete="username" required>

  <label for="mdp">Mot de passe</label>
  <input id="mdp" name="password" type="password"
         autocomplete="current-password" required minlength="8"
         aria-describedby="aide-mdp">
  <p id="aide-mdp">8 caractères minimum.</p>

  <fieldset>
    <legend>Profil</legend>
    <input type="radio" id="p-dir" name="role" value="directeur" checked>
    <label for="p-dir">Directeur</label>
    <input type="radio" id="p-mag" name="role" value="magasinier">
    <label for="p-mag">Magasinier</label>
  </fieldset>

  <button type="submit">Se connecter</button>
</form>
§explain
<ul>
<li><code>name</code> est la clé de la donnée envoyée ; <code>id</code> sert au label et au CSS/JS.</li>
<li><code>autocomplete="username"</code> / <code>current-password</code> aide le gestionnaire de mots de passe.</li>
<li><code>aria-describedby</code> fait lire l'aide après le label.</li>
<li>Les boutons radio d'un même groupe partagent le même <code>name</code> : un seul choix possible.</li>
<li><code>novalidate</code> désactive les bulles du navigateur pour afficher nos propres messages en JS (chapitre Formulaires JS). Sans lui, la validation native s'applique.</li>
<li><code>type="submit"</code> : le bouton envoie le formulaire. <code>type="button"</code> ne l'envoie pas.</li>
</ul>

§§chapter html-tableaux
part: html
title: Tableaux de données
subtitle: table, caption, thead, tbody, tfoot, th et scope
duration: 1 h
feature: Liste des commandes et lignes d'une commande
§intro
<p>Un tableau HTML sert à présenter des <strong>données à deux dimensions</strong> : des lignes (une commande par ligne) et des colonnes (numéro, client, statut, montant). On ne s'en sert <strong>jamais</strong> pour faire de la mise en page.</p>
<p>Structure : <code>&lt;table&gt;</code> contient un titre <code>&lt;caption&gt;</code>, une tête <code>&lt;thead&gt;</code>, un corps <code>&lt;tbody&gt;</code> et éventuellement un pied <code>&lt;tfoot&gt;</code> pour les totaux. Chaque ligne est un <code>&lt;tr&gt;</code> ; une cellule d'en-tête est un <code>&lt;th&gt;</code>, une cellule de donnée un <code>&lt;td&gt;</code>.</p>
<p>L'attribut <code>scope="col"</code> ou <code>scope="row"</code> sur <code>&lt;th&gt;</code> indique si l'en-tête concerne une colonne ou une ligne.</p>
§example html
<table class="table">
  <caption>Lignes de la commande CMD-2026-0042</caption>
  <thead>
    <tr>
      <th scope="col">Produit</th>
      <th scope="col">Qté</th>
      <th scope="col">PU HT</th>
      <th scope="col">Total HT</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Vis inox 4x40</th>
      <td>10</td><td>8,50 €</td><td>85,00 €</td>
    </tr>
    <tr>
      <th scope="row">Perceuse 18 V</th>
      <td>1</td><td>129,00 €</td><td>129,00 €</td>
    </tr>
  </tbody>
  <tfoot>
    <tr><th scope="row" colspan="3">Total HT</th><td>214,00 €</td></tr>
    <tr><th scope="row" colspan="3">TVA 20 %</th><td>42,80 €</td></tr>
    <tr><th scope="row" colspan="3">Total TTC</th><td>256,80 €</td></tr>
  </tfoot>
</table>
§explain
<ul>
<li><code>&lt;caption&gt;</code> donne le titre du tableau : il est annoncé en premier.</li>
<li>Le nom du produit est un <code>&lt;th scope="row"&gt;</code> : c'est l'en-tête de sa ligne.</li>

§§chapter html-accessibilite

subtitle: alt, ARIA, focus, régions live, dialog, structure de projet

§intro
<p>L'<strong>accessibilité</strong> (a11y) consiste à rendre l'application utilisable par tout le monde : personnes aveugles (lecteur d'écran), malvoyantes (zoom, contraste), qui n'utilisent que le clavier, daltoniennes, ou simplement sur un téléphone en plein soleil. En France, c'est aussi une obligation légale pour de nombreux services.</p>
<p>Les bonnes pratiques clés :</p>
<ul>
<li>Utiliser d'abord le <strong>bon élément HTML</strong> : un <code>&lt;button&gt;</code> est déjà focusable et activable au clavier, une <code>&lt;div&gt;</code> non.</li>
<li>ARIA seulement en complément : <code>aria-label</code> (nom), <code>aria-expanded</code> (ouvert/fermé), <code>aria-live</code> (annoncer un changement).</li>
<li>Ne jamais transmettre une information par la <strong>couleur seule</strong> : un statut « En retard » a une couleur <em>et</em> un texte ou une icône.</li>
<li>Le focus doit être <strong>visible</strong> et suivre un ordre logique.</li>
</ul>
<p>Côté organisation, un projet propre sépare <code>index.html</code>, un dossier <code>css/</code>, un dossier <code>js/</code> et un dossier <code>assets/</code> (images, icônes, polices).</p>
§example html
<!-- Bouton icône : le texte invisible donne son nom -->

        aria-expanded="false" aria-controls="panneau-notifs">
  <svg aria-hidden="true" width="20" height="20"><use href="#i-bell"></use></svg>

</dialog>
§explain
<ul>
<li>Un bouton qui ne contient qu'une icône doit avoir un <code>aria-label</code> ; l'icône a <code>aria-hidden="true"</code> pour ne pas être lue.</li>
<li><code>aria-expanded</code> dit si le panneau commandé est ouvert ; le JS le met à jour.</li>
<li><code>aria-live="polite"</code> : tout texte ajouté dans la zone est lu dès que l'utilisateur fait une pause. On l'utilise pour les messages « Commande enregistrée ».</li>
<li><code>&lt;dialog&gt;</code> ouvert avec <code>showModal()</code> bloque le reste de la page, piège le focus et se ferme avec Échap.</li>
<li>Dans un <code>&lt;form method="dialog"&gt;</code>, cliquer sur un bouton ferme la boîte et donne sa <code>value</code> à <code>dialog.returnValue</code>.</li>
</ul>

§quiz
? Quelle est la première règle de l'accessibilité en HTML ?
+ Utiliser le bon élément natif avant d'ajouter de l'ARIA
- Ajouter role="button" partout
- Utiliser des div
- Mettre aria-label sur tout
= « Pas d'ARIA vaut mieux qu'un mauvais ARIA. »
? Que fait aria-live="polite" ?
- Rend un texte plus poli
+ Fait annoncer les changements de contenu de la zone
- Cache la zone
- Rend la zone cliquable
= Idéal pour les notifications de succès.
? Un bouton qui contient seulement une icône doit avoir…
- Un title uniquement
+ Un nom accessible, par exemple aria-label
- Rien
- Une classe icon
= Sans nom, le lecteur d'écran dit seulement « bouton ».
? Pourquoi ne pas indiquer un retard uniquement en rouge ?
- Le rouge est démodé
+ Les personnes daltoniennes ou malvoyantes ne percevront pas l'information
- Le rouge ne s'imprime pas
- Ce n'est pas un problème
= Critère WCAG 1.4.1 : utilisation de la couleur.
? Quel avantage de <dialog> avec showModal() ?
- Il est plus joli
+ Il gère la modalité, le focus et la touche Échap
- Il fonctionne sans JavaScript
- Il remplace les formulaires
= Moins de code à écrire et un comportement accessible par défaut.
